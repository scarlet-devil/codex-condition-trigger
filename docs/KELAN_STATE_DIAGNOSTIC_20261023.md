## 1. 可接受的结论

这次原生查询明确在 `current_state` 的 cwd 比较处被拒绝，原因码为 **`snapshot_cwd_mismatch`**。同一个失败调用中的预期 cwd 来自已核验目录记录，采用干净的扩展盘符形式；native state 的 cwd 采用普通绝对盘符形式。二者原文及旧 `normcase(normpath(...))` 比较不相等，现有受限目录 helper 则将它们规范化为相同字符串。这定位了**本次样本的具体拒绝条件及表示差异**。它没有证明此前仅记录 `protocol` 的样本也是同一原因，也没有证明规范化后的路径必然具有文件系统对象身份。

Tk 成功打开自己的目录选择器，选中预定合成目录，画面显示 `Directory check: True`，本地回执同时记录 `selection_matches=true`、`closed=true`、`timed_out=false`，进程退出码 0。此次操作有用户明确给予的短时无并发键鼠间隙，开始、异常恢复和结束均告知。此前失败的 Tk 记录保留为历史，没有覆盖。

**原生 runtime 状态仍为 unknown，can_send=false。** 未绕过拒绝点继续解释 idle；未重新查询；未发送初始化、样例、追问或业务任务。本轮没有修改生产 native 路径比较、监听配置、安装包或业务 ACK。

因此，磁盘上的固定输入源码未改，但**不能称执行时完全没有插桩**。附上的 [观察器](../evidence/support/cwd_observation.py)与[三项合成检查](../evidence/support/test_cwd_observation.py)用于审计，不是候选路径修复或生产依赖。重放这些合成检查可将两文件放到固定输入的隔离根目录，再执行 `python -B -m unittest test_cwd_observation -v`；不需要真实 IPC。
