# 三项配置使用说明：Windows Desktop

选择“文件夹、触发条件、目标对话”，让本地监听器在新文件内容稳定后通知指定聊天。触发后的指令可选；默认忽略启用时已有的内容，普通通知无需逐批业务 ACK。

本文件沿用 G2 时的路径，现已补齐 G3 后的说明。G0—G3 的限定验收覆盖当前已验证安装、已打开且准确绑定的专用对话及本次工作量；不代表已合并、安装或启用生产，也不承诺任意 Desktop 版本可用。详见[当前状态](../CURRENT_STATE.md)和[第18节](KELAN_THIN_STATE_NEXT_STEPS_20261023.md#18-当前结论g3-双批专测限定接受进入交付收尾)。

## 准备与入口

本 PR 合并前，默认 `main` 尚不包含表单。首次使用可在一个新的目录取得候选分支；不要覆盖已有工作目录：

```powershell
git clone --branch draft/three-field-setup-design --single-branch https://github.com/scarlet-devil/codex-condition-trigger.git codex-condition-trigger-setup
cd codex-condition-trigger-setup
git rev-parse HEAD
py -3 -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
```

核对 `git rev-parse HEAD` 与当前 PR Head；分支名称会随提交移动，不是固定版本证明。已有候选副本可使用其虚拟环境，在仓库根目录运行。需要 Python 3.10+、Tk 和 requirements.txt 中的 watchdog==6.0.0。`py -3` 使用已安装的 Python launcher；若没有 launcher，改用已安装 Python 的准确路径创建环境，不依赖可能指向 Windows 应用商店的 `python` 别名。后续命令统一使用虚拟环境解释器。

查看参数不会打开窗口、连接聊天或发送任务：

```powershell
.\.venv\Scripts\python.exe -B .\simple_setup.py --help
```

首次尝试可用模拟模式，传入一个尚不存在的隔离目录：

```powershell
.\.venv\Scripts\python.exe -B .\simple_setup.py --simulate "$env:TEMP\codex-trigger-form-demo-01"
```

模拟模式显示 fake 标记，创建合成输入和两个同名对话，不连接真实 Desktop、不发模型任务。非空目录会拒绝初始化；已有空目录也可使用。建议每次换用新目录，保留失败记录。

接入真实目标前，先在同一 Windows 用户的 Desktop 中明确打开准确的专用聊天，然后启动真实表单：

```powershell
.\.venv\Scripts\python.exe -B .\simple_setup.py
```

此命令打开表单并读取本机聊天目录元数据；监听和真实发送由“启用监听”开始。不需要绑定 Codex 原生定时自动化，也不自动注册系统服务或登录任务。监听器在表单进程内运行，需要让该进程持续运行。

## 三项填写与启用

1. **文件夹**：选本地投送目录。扫描递归处理子目录；临时文件、Git 目录等排除项见预览。规则状态必须位于输入目录之外，不能相互嵌套。
2. **触发条件**：选“新内容写入稳定后”，或“出现 READY 且内容稳定后”。后者要求生产者在写入前移除旧 READY，内容写完后最后重建标记。标记不能绕过稳定性检查。
3. **目标对话**：按标题或项目搜索，核对项目、更新时间和区分标识。同名对话不能只凭标题选择。选中目录记录不会打开聊天，也不证明 owner 已可用。

高级选项默认稳定时间 **120 秒**、初始策略为“忽略现有文件”。可选指令告诉目标如何处理新材料；来源材料里的指令不提供额外授权。预览的内容数量是当时观察，初始基线以**实际启用时**为准。

点击“预览”核对目录、递归/排除项、稳定时间、初始策略、目标和指令，再“启用监听”。首次启用会核对准确目标的当前连接和空闲状态；检查失败则没有成功启动监听，应先处理原因。等待显示“监听中”和新鲜扫描进展，不能只看“规则已启用”。

运行中目标忙碌或连接不可用时保留批次。A 已被准确接收且正在执行时，B 等待；A 对应回合结束，并确认目标重新空闲后，才投递 B。仅时间戳变化或相同字节重复出现，不会作为新内容重复通知。

## 暂停、恢复、最小化、关闭

| 操作 | 实际作用 |
| --- | --- |
| 暂停 | 持久暂停规则，停止本窗口监听 worker；保留基线、批次和不确定发送记录。 |
| 恢复 | 恢复同一已初始化规则，核对保存的配置与绑定，发送时重新检查目标；不重建初始基线，不延长已过期的试验。 |
| 最小化 | 窗口退到任务栏，监听继续。 |
| 关闭 | 先暂停，等待 worker、observer 和锁释放后退出；不关闭用户的 Codex 聊天窗口。 |
| 读取已有规则 | 只载入保存信息，不自动恢复。独立重开 GUI 的完整实机流程尚未新增验收。 |
| 新规则 | 更改已建立规则的目录、条件或目标时，先暂停，再建立独立规则；保留旧证据。 |

暂停或关闭不取消 Desktop 已接受的模型任务；如需取消，在目标聊天处理。Windows 真实规则保存在当前用户 `%LOCALAPPDATA%\codex-condition-trigger\simple-rules`，聊天目录来自解析后的 CODEX_HOME。不要把含私人聊天标识的规则或日志直接上传公开仓库。

## 如何判断进展或阻点

| 界面现象 | 含义与处理 |
| --- | --- |
| 监听中，扫描进展持续更新 | 本窗口 worker 正在运行；不表示每批任务执行或交付成功。 |
| 规则已启用，但本窗口没有运行中的监听器；或进度需检查 | 配置状态不等于进程健康。核对暂停、异常信息与现存 worker，不能假定监听正常。 |
| 等待连接／目标空闲 | 保留材料，确认准确专用聊天已打开；正在执行时等待，不新开替代宿主。 |
| 投递结果不明，等待核对 | 可能已经被接收。核对原批次和准确回合，不通过删状态、换批次或重复启用强制重发。 |
| 回合结束，业务未验收 | 普通通知的调度状态，不是成果正确或上传成功的证明；另行核验结果与交付。 |
| 目录记录过多 | 收窄标题/项目搜索后重新读取。 |
| 目录不可读或 schema 不支持 | 核对目录来源、读取错误及版本；不手改 Desktop 数据库或把未知 schema 当成空列表。 |

旧严格模式继续保留业务交付验收规则。普通通知解除排队不伪造业务 ACK；上传续传是独立功能，本表单不自动完成 Drive 业务交付。

## 无模型的模拟练习

在新 --simulate 目录中，选择合成 input 和标识以 00000002 结束的第二个同名目标。可临时把稳定时间改为 1 秒，预览、启用后等待新鲜扫描。点“写入 A”，接收后写入 B，B 应等待。点“结束模拟回合”，A 结束后 B 自动接收；再结束一次，积压归零，业务仍未核验。可继续检查暂停、恢复、最小化与关闭。

这是模拟器说明，不是重做 G3 的指令。G3 的 480 秒、最多两次发送和 180 秒发送余量属于当次监督试验，**不是所有日常规则的固定运行期限**。
