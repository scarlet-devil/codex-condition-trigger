# G2 三项配置候选

本说明对应 G2 模拟验证候选；真实 Desktop 两批验收属于 G3。依赖沿用仓库 requirements.txt 与带 Tk 的 Python，不需要新增系统服务。

从仓库根使用已配置的解释器，选一个新的、空的试验目录：

```powershell
python -B simple_setup.py --simulate '<新的空试验目录>'
```

模拟模式会明确显示 fake 标记，创建合成目录与两个同名对话，并把规则、锁和日志隔离在该目录。既有目录拒绝复用；失败证据不会被初始化覆盖。

1. 点击“选择文件夹”，确认默认的合成 input；条件保留“新内容写入稳定后”，选择区分标识以 00000002 结束的第二个同名目标。
2. 展开高级选项可查看默认 120 秒、忽略初始内容及可选指令。烟测可手工改成 1 秒；这不改变产品默认值。
3. 预览核对目录、递归/排除项、稳定时间、初始策略和目标，再启用；等待“监听中／扫描 ok”，不能只看按钮完成。
4. 点“写入 A”，待已接收后写入 B；B 应等待。点“结束模拟回合”，A 结束后 B 自动接收；再结束一次，积压归零，业务仍未核验。
5. 暂停后恢复同一规则，原基线和批次保留；最小化继续监听；关闭会持久暂停并等待 worker、observer 和锁释放。

重开规则的控制器路径只读取本工具保存且完整的规则，不会自动恢复。配置或库缺失、绑定/清单冲突需核对，不自动修补。更改规则输入需先暂停并新建独立状态。普通通知不需要业务 ACK；旧 strict 模式保护不变。

本轮只运行了 --simulate。无该参数的入口会读取当前 CODEX_HOME 下的目录元数据，在用户明确启用规则时接入真实适配器；不要把 G2 模拟通过当成该真实链路已验收。

无窗口专项测试沿用 unittest（仓库根与 tests 加入 PYTHONPATH）：

```powershell
python -B -m unittest discover -s tests -p 'test_simple_*.py' -v
```

全套检查按 AGENTS 使用已核对的冻结 Hub src，避免把可选依赖缺失的跳过当作集成通过。目录默认 TEMP 必须对运行账户可写；本轮使用隔离的可写 temp，不修改系统 TEMP 或权限。

限制与实际结果见 [G2 报告](KELAN_G2_FORM_20261024.md)。
