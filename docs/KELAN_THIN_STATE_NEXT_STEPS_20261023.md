### 6.1 对加载问题的判断

候选逻辑确实局限于三份模块、六个插入/替换点。现在新增的是安装与信任耦合，不能把它继续描述为只改一个窗口字段，也不能据此断言必需重写 Desktop。

[Electron 官方机制](https://www.electronjs.org/docs/latest/tutorial/asar-integrity)要求受保护的 ASAR 头与宿主打包时提供的摘要相符；Windows 使用 `Integrity` / `ElectronAsar` PE 资源。固定 fuse 源码映射也支持报告中索引 4/5 已开启的解释。因此，在本机报告前提成立且采用该标准机制时，“只改模块并重打 ASAR 不足以加载”是有依据的推断；没有执行失败启动来制造证据。

**fuse 位于 chrome.dll，不等于摘要资源也位于 chrome.dll。** 当前材料还未读出该资源和原 ASAR 头的对应关系，也未明确包身份、签名覆盖和可用恢复单位。DLL 签名有效不能单独证明完整安装信任路径。

重新计算摘要与数字签名是不同步骤。按 [Microsoft 的 PE 签名规则](https://learn.microsoft.com/en-us/windows/win32/debug/pe-format#process-for-generating-the-authenticode-pe-image-hash)，改动正常签名覆盖的资源内容会使该文件原签名不再匹配；本机另签不能恢复为原厂签名。具体受影响文件尚待核对。

路线判断：**保留完整性检查，先准备具体的受控加载方案；当前不选择关闭 fuse、忽略签名或改装运行中安装。** 受支持宿主提供摘要接口仍是长期优先路线，但目前未取得。自管服务和另一个 Desktop 副本不能替代“原 Desktop 既有会话”的验收目标。

### 8.1 本轮已经准备好的计量工具

云端新增 [snapshot_measure.py](../experimental/snapshot_measure.py)，复用原 `IPCClient.current_state` 的 owner/thread/cwd/revision 检查。它只允许初始化、owner 查询、既有完整历史查询及临时订阅/取消订阅，不能发送模型任务；没有 CLI、自动发现管道或生产接线。调用者传入经本机目录/rollout 核对的 thread/cwd 和一条新管道，函数核验原安装、采一次样后关闭连接。

```python

from experimental.snapshot_measure import measure_snapshot

# verified_thread_id / verified_cwd 来自本机准确选择；不要提交私人标识。
sample = measure_snapshot(WindowsPipe(), verified_thread_id, verified_cwd)
```

固定本轮安装归档 SHA-256 为 `a05dfd86ca508148c83c25590639cf91a52c6647733cdf200723d85357052b49`，变化则停止适配，不自动放宽。单帧正文沿用 **32 MiB**；每连接累计读取预算 **128 MiB**（包括帧头及无关通知，为旧路径可能重复推送快照留出空间）；安装核验后初始化至最后 owner 复查/清理共用 **10 秒单调截止**。没有自动重试。该预算适用于本次完整快照观测，不冒充薄摘要的 64 KiB/1 MiB 契约，也没有改生产限额。

输出仅包含状态、revision、总量/最大帧/耗时和固定错误类别；`can_send` 永远为 false。`target_snapshot` 大小只表示帧标注目标，原生有效性另由既有 current_state 核对。失败的底层 I/O 可能部分完成，因此区分已完成读取字节和提前扣除的读取预算，不把前者冒充精确线上总量。安装签名/归档读取另记耗时，JSON 解析不能被截止时钟抢占；不宣称全进程严格 10 秒硬终止。

[合成检查](../experimental/tests/test_snapshot_measure.py)覆盖预算、噪声、截止、超限正文拒读、目标/owner 错配、只读白名单、脱敏及清理失败。云端通过不替代 Windows 验证。

### 12.3 实现范围与顺序

1. **先把通知推进与业务交付分开。** 新简易规则显式写入 dispatch_mode=notify；没有新字段的旧配置保持 verified_delivery，不给旧数据库自动补初始基线，也不把历史 pending 批次转换成 notify。模式、schema 和准确目标绑定到独立规则状态，不允许在含历史的状态目录上切换。首版 notify 仅接已验证的 desktop_ipc 语义；其他适配器组合应在外发前明确拒绝，不默默降级。G1 用同契约 fake adapter 注入测试。
2. **持久保存通知证据并据此选择下一批。** 复用先落盘意图再发送的顺序；保存 batch、manifest 哈希、thread/cwd、request/client-message、原生 receipt turn 与来源，终止证据必须绑定同一准确 turn。把通知释放资格放在独立字段/表或等价投影中，不改 delivered 的含义，不伪造 ACK，也不删除 A 的历史。状态字符串 ended/completed/failed 本身不能放行；只有可信接收关联、准确终止、重新空闲且当前 STOP/期限允许时才能推进。execution_outcome=unknown 不等于终止未知：准确结束但业务结果未知仍可继续，未知接收或缺终止证据必须等待核对。
3. **沿用现有收发链路，收紧新模式的证据来源。** 当前 dispatch_one 选择首个未交付批次并在 ended/completed 等状态停下，需要按模式选择候选；真实入口经过 owner_loading.cycle_tick，不能只改内部选择函数而漏掉 run/dispatch 接线。当前 DesktopAdapter.observe 可凭已知 turn 读取 rollout 生命周期，也有纯文本恢复后备；notify 首版的自动推进要求原生接收 turn + post-intent baseline + 同一完整投递文本和准确终止记录。仅靠文本猜到的 turn 不自动解锁后批，保留其来源不认证/人工复制可混淆的边界。无需为普通通知打开 native_result_collection 或自动写业务成功；旧严格模式的既有恢复语义保持。
4. **补薄规则编译与初始基线。** 不先做 GUI。提供可被将来表单调用的预览、启用、暂停/继续和状态接口，名称由最小实现确定。输入为文件夹、两种既定条件预设及目录选择返回的准确绑定，不要求用户输入内部标识。编译器生成私有运行配置、规则 ID/修订及现有默认值；非法目标、相互嵌套目录等在启用前拒绝。预览只计算摘要/检查，不创建业务库、不推进版本/批次/基线、不发送模型。启用默认 initial_files=ignore，以独立 baseline_versions 或等价结构保存已扫描版本；完整保存后才进入 enabled，失败/中断不能留下半初始化状态。不得用 seed/假 delivered 实现初始忽略；处理当前已有内容仍是显式高级选项。暂停/重启沿用原基线，恢复只补扫仍存在的新内容。
5. **保证状态、互斥和恢复一致。** 每批固定创建它的规则修订；接收/终止证据与对应状态原子保存。保留已证实未写出的原有恢复路径；发送结果不明、回执落盘前崩溃或多义匹配不得重发或跳过该批。本工具管理的同一目标最多一条启用规则；按稳定 thread 共享锁，不能把仅按 state_dir 的 InstanceLock 当成跨规则互斥。锁只约束本工具，发送前仍核对原生状态，不宣称约束用户/其他客户端或消除 idle/start 竞态。新 notify 状态要有实际旧版本拒写保护；可复用既有 binding 不匹配机制，但必须用旧程序验证，不能只增加一个旧程序不会读取的版本字段。回退用保留的旧配置/库，不删列伪装回退。
6. **提供真实的状态与资源边界。** 按投递、回合、业务三轴输出状态，明确等待空闲、等待连接、已接收/运行中、已结束和需要核对；失败结果不能被“可继续”遮住。积压按尚未释放的通知批次计算，不能继续将所有 state!=delivered 永久计入 notify 待办。沿用设计的暂定上限：100 个尚未结束/释放的冻结批次、1 GiB 状态总量；达到批次上限停止新增冻结但允许既有批次推进，容量不足停止新增冻结和发送，保留历史并给出原因，不自动删证据。先以小阈值夹具测试边界，不制造大文件压力工程。保留现有扫描稳定、SHA 去重、READY、STOP/绝对期限/单调预算契约。

### 13.3 从按钮到监听的接线约定

**启用成功不等于监听已经运行。** `rule_service.enable`当前只核验并初始化规则，它不会启动`run`。G2控制器必须负责这一步，同时让界面响应保持可用。

- 推荐Tk主线程只处理控件；文件预览、启用和监听在受管工作线程中执行，结果通过队列回到主线程。每个工作线程在自己的线程内创建/关闭Store与SQLite连接；不跨线程共享连接，不从后台直接写Tk控件。不需要新后台服务或常驻子进程。当前run未提供adapter_factory参数；G2可增加窄的显式依赖注入入口以测试完整监听链路，或采用范围受控的测试替身，禁止测试传输失败后落到真实IPC。
- 表单变化使旧预览失效；待预览/启用时禁止重复提交。异步结果带当前表单代次/操作ID，迟到结果不得覆盖新选择、取消或成功暂停。点击启用使用已展示摘要对应的配置；启用重新扫描得到的基线数量如有变化，展示最终提交数量，不能把预览计数当作已提交事实。
- 初始化完成后启动受管worker，复用现有run/cycle_tick。启动失败保留原配置/基线并停用该规则，显示失败原因，之后通过恢复重试，不再调用enable重建基线。新worker必须取得G1锁，不能因UI判断“已经退出”绕过锁。双击、多个表单或同目标竞争只能有一个有效运行者。
