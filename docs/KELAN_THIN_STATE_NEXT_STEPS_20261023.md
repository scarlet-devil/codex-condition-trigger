### 6.1 对加载问题的判断

候选逻辑确实局限于三份模块、六个插入/替换点。现在新增的是安装与信任耦合，不能把它继续描述为只改一个窗口字段，也不能据此断言必需重写 Desktop。

[Electron 官方机制](https://www.electronjs.org/docs/latest/tutorial/asar-integrity)要求受保护的 ASAR 头与宿主打包时提供的摘要相符；Windows 使用 `Integrity` / `ElectronAsar` PE 资源。固定 fuse 源码映射也支持报告中索引 4/5 已开启的解释。因此，在本机报告前提成立且采用该标准机制时，“只改模块并重打 ASAR 不足以加载”是有依据的推断；没有执行失败启动来制造证据。

**fuse 位于 chrome.dll，不等于摘要资源也位于 chrome.dll。** 当前材料还未读出该资源和原 ASAR 头的对应关系，也未明确包身份、签名覆盖和可用恢复单位。DLL 签名有效不能单独证明完整安装信任路径。

重新计算摘要与数字签名是不同步骤。按 [Microsoft 的 PE 签名规则](https://learn.microsoft.com/en-us/windows/win32/debug/pe-format#process-for-generating-the-authenticode-pe-image-hash)，改动正常签名覆盖的资源内容会使该文件原签名不再匹配；本机另签不能恢复为原厂签名。具体受影响文件尚待核对。

路线判断：**保留完整性检查，先准备具体的受控加载方案；当前不选择关闭 fuse、忽略签名或改装运行中安装。** 受支持宿主提供摘要接口仍是长期优先路线，但目前未取得。自管服务和另一个 Desktop 副本不能替代“原 Desktop 既有会话”的验收目标。

### 8.1 本轮已经准备好的计量工具

云端新增 [snapshot_measure.py](../experimental/snapshot_measure.py)，复用原 `IPCClient.current_state` 的 owner/thread/cwd/revision 检查。它只允许初始化、owner 查询、既有完整历史查询及临时订阅/取消订阅，不能发送模型任务；没有 CLI、自动发现管道或生产接线。调用者传入经本机目录/rollout 核对的 thread/cwd 和一条新管道，函数核验原安装、采一次样后关闭连接。

```python
# verified_thread_id / verified_cwd 来自本机准确选择；不要提交私人标识。

```

固定本轮安装归档 SHA-256 为 `a05dfd86ca508148c83c25590639cf91a52c6647733cdf200723d85357052b49`，变化则停止适配，不自动放宽。单帧正文沿用 **32 MiB**；每连接累计读取预算 **128 MiB**（包括帧头及无关通知，为旧路径可能重复推送快照留出空间）；安装核验后初始化至最后 owner 复查/清理共用 **10 秒单调截止**。没有自动重试。该预算适用于本次完整快照观测，不冒充薄摘要的 64 KiB/1 MiB 契约，也没有改生产限额。
