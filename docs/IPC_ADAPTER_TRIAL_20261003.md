## 目标与本轮授权

红魔同意先试验“文件条件核心 + 独立聊天接口 + Desktop IPC 适配器”，并要求记录备选方向、发送下一步指示。交付一个可运行候选，完成当前 Windows 环境的一次有界真实链路小试，再报告结果与维护成本。

保留“在指定的原 Desktop 聊天继续执行”的目标。监听、稳定判断、去重、固定文件版本、SQLite 待办和业务 ACK 继续由触发器核心负责。聊天未加载、owner 不可用或适配器不兼容时，只暂停相应投递；本地监听、批次保存与状态查询继续可用，不丢弃或重复发送待办。

本轮包括必要实现、隔离回归、只读宿主检查以及下述合成材料试验；同范围工作不需要再次请求抽象方案批准。当前文档不是已完成的本机验收。现有周期机制保留，试验使用独立输入/状态，避免同时处理真实材料。合并、正式切换、自启动、强制 Desktop 更新/重启和权限/凭据修改不在这次小试内。

- `886755e` 云端 Linux 回归为 44 项通过。
- 柯蓝 Windows 报告：原版 42 通过、1 清理错误、1 跳过；仅关闭遗漏 SQLite 连接的诊断副本为 43 通过、1 跳过。原生文件监听 dry 验收 14/14 通过。归属是柯蓝，爱丽丝本轮仅回读报告。原失败不能改写为原版全部通过。
- 当前触发器尚未验收原 Desktop 链路、原工具/Hook 或业务交付。默认控制 socket 缺失及字节 proxy 的限制，只说明那条接入路径未闭合。
- 既有私有项目曾通过相同 Desktop IPC 路径完成原聊天两轮接续。它提供可复用经验，不证明当前新机、版本或这个触发器已经兼容。私人源码位置、原始回执和目标绑定沿用本机已获授权的记录，不搬进公开仓库。
- 旧路径的维护负担混合了整包路径/哈希绑定、owner 生命周期、内部权限字段语义和观察器实现缺陷。不能把每次更新都归类为 IPC 协议破坏，也不能承诺所有未来版本兼容。

## 实现边界

采用最小接口即可，不新增通用插件框架。以下是职责示意，方法名由实现决定：

| 能力 | 核心需要知道的结果 |
| --- | --- |
| 检查目标 | 准确目标/宿主关系，以及可投递、忙碌、未加载、不可用或不兼容；未知不能当空闲 |
| 投递固定批次 | 确定未派发、已接受并带可核对标识，或结果不明 |
| 查询已有投递 | 对应批次的排队/运行/完成/失败及证据；不触发新的模型工作 |

Desktop 安装路径、管道、owner 发现、消息帧和私有字段只能留在适配器内。现有 JSONL/queue 实现可成为一个后端，IPC 为另一个后端；不要求 IPC 伪装成官方队列服务。

当前核心直接依赖 `thread/read`、`thread/queue/list`、`thread/queue/add`。IPC 的 start-turn 回执不是 queue/add 回执：明确调整接口和状态映射，不能制造队列项或声称已由宿主排队。如果 IPC 后端没有已验证的队列能力，忙碌时保留本地待办并延后投递，不 steering、不打断原回合。保留现有 single-worker、sending 意图、ACK 终态保护和 uncertain 不自动重发的约束；不承诺全局 exactly-once。

优先复用已有实现中通用的帧传输、owner 定位与回执关联，剥离固定私人绑定及旧权限写入/恢复逻辑。使用外部源码时固定来源并遵守许可证，公开提交只包含可公开的通用代码、匿名夹具与脱敏证据。

## 版本解耦与结果判断

- 自动定位可信来源的当前安装；版本、路径、包摘要记录为环境来源。整包摘要变化不单独等于协议失败，也不通过简单删除旧守卫来接受任意目标。
- 只核对实际使用的方法、必要字段、目标路由及设置继承。协议方法版本与应用版本分开；支持范围明确，不能自动试发多个方法版本直到某个成功。
- 不引入新的模型、cwd、审批或沙箱设置，不复制旧适配器的强制 readOnly/never 策略。核对当前发送契约中省略字段及继承标志的真实含义；如必须提供上下文，证明它表达原设置而非另设权限。
- 对无关新增通知和已识别的上下文记录保持兼容，但不能泛化丢弃工具/动作记录、关键字段或目标不匹配。缺证据如实保留，不只看最终回答“像是正确”。
- 明确区分消息接受、准确回合开始、回合结束与业务 delivered；优先使用真实 request/client/thread/turn 关联。只有文本匹配时，保留现有非认证关联限制。
- 握手/只读成功不是完整发送验收。最终失败也不自动归因 IPC；区分传输、目标不可用、协议、模型执行与业务结果。
- 一次当前版本成功只能证明该环境的限定链路。合成版本字段/额外通知或历史记录回放，只证明对应测试边界；真正跨版本持续可用留待自然更新机会验证，不为本轮强制更新应用。

## 有界小试步骤

1. 核对本机当前入口与准确目标。沿用原项目已登记的目标，或使用已明确指定的隔离测试聊天；测试时须空闲且不与另一个写入者并发。不得按标题相似度猜目标，不能用新起 app-server 或另一个 SDK thread 冒充原聊天。身份不清时，完成其余隔离工作后返回具体缺口。
2. 实现适配器边界与受影响测试。可并入已定位的 SQLite 测试连接关闭修订，保留原失败证据。重点覆盖：不可用时核心仍保存批次、busy 不派发、不确定发送不重放、回执关联和无关通知兼容。只复跑受影响范围及必要既有回归，不另起全面验收工程。
3. 用现有安装和最小只读查询确认原目标的可用 owner 与必要协议能力；不扫描无关聊天，不读取凭据，不强制加载/重启整个应用。原目标暂不可用是正常待办状态，不以重复连接生成模型回合。
4. 首轮以一个合成文件、一个批次和一次实际投递为目标。文件含唯一标记及已知内容，保存固定快照；发给目标的测试任务只用原会话已有的必要读取工具读取该快照并返回标记与指定结果，不修改真实项目或调用外部写入。记录批次、原聊天、原回合和实际工具回执的关联。确定未派发时可在本范围修正后继续；已经接受或结果不明时只核对原尝试，不自动重发。
5. 用现有 Hook 的真实适用事件核对本轮继承；不为凑验收新增 Hook 或扩大其范围。未出现适用事件则记未覆盖，不把工具可用推成全部 Hook 已通过。工具/Hook 有缺口时，仍回报已经取得的接入结果，不宣称完整替换能力。
6. 根据实际内容与回执独立核对这一合成任务。可为本地小试生成局部核验回执并 ACK，但只能称“合成试验的本地核验”，不得宣称外部交付系统已接通。重复相同字节应无新增投递；停止 watcher 后不再新增派发，已接受的原回合按宿主实际状态报告。
7. busy、未加载、应用重启与跨版本中的未出现分支，用隔离替身或已授权留存记录覆盖并明确标注；不关闭其他工作窗口来制造故障，也不把模拟结果充作现场实测。

成功标准是：在当前环境中观察到固定材料到达、正确原聊天的一次目标回合、可关联的真实结果，并证明聊天不可用不会破坏本地待办。功能/工具/Hook/业务与跨版本证据分别报告。若小接入仍要求频繁改写内部权限状态或大范围逆向，记录具体依赖和本轮花费，返回路线取舍；不要自动扩大为新的维护系统。
