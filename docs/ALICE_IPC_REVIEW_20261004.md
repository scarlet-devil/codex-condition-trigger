## F1：外部回复形状错误会逃出投递边界（P2，已复现）

位置：[IPC 回复解析](https://github.com/scarlet-devil/codex-condition-trigger/blob/93d84fdd4be5d6ed7b9ea9317a3326489a12a41b/desktop_ipc.py#L270-L279)、[start-turn 回执读取](https://github.com/scarlet-devil/codex-condition-trigger/blob/93d84fdd4be5d6ed7b9ea9317a3326489a12a41b/desktop_ipc.py#L355-L359)及[核心异常边界](https://github.com/scarlet-devil/codex-condition-trigger/blob/93d84fdd4be5d6ed7b9ea9317a3326489a12a41b/trigger.py#L392-L406)。

合法 JSON 的 `null` 帧使 `item.get` 抛出 AttributeError；模拟已写出 start-turn、但返回 `{"result": null}` 时，嵌套读取抛出 TypeError。两者都不在核心的受控异常路径中。后一个探针直接观察到异常逃出 `dispatch_one`、状态停在 sending；重新打开数据库会正确转成 uncertain，并可用已有记录关联回合，模拟发送总数仍为 1。

根据 `run` 的调用/异常路径，这类异常会结束 live 监听循环。这一后果来自源码控制流判断，本轮未运行真实 watcher 故障实验。它违反“聊天后端不兼容只暂停投递、文件监听继续工作”的当前接口目标；不是已经观察到的 Windows 生产崩溃。

请在外部协议边界校验对象及必要嵌套字段的类型，转换成已有受控协议异常。确定未发送时保留本地待办；写出后无法确认的回复必须保留 uncertain，不能当作未发送。复用现有 watcher 故障隔离测试，定点覆盖异常帧/回执后仍能捕获后到文件以及不重复投递；不要用全局吞掉所有异常来掩盖程序错误。

## F2：turn_interrupted 未被识别（兼容性线索，现场原因未确认）

候选的[终止事件集合](https://github.com/scarlet-devil/codex-condition-trigger/blob/93d84fdd4be5d6ed7b9ea9317a3326489a12a41b/desktop_ipc.py#L66-L83)没有 `turn_interrupted`，而已固定采用的[第三方协议参考](https://github.com/Destiny-Rul/CodexAgentControl/blob/76408870888198f7ee3973b807d2302a86236143/skills/codex-desktop-control/references/protocol.md)明确列出它。

合成序列 `start A → turn_interrupted A` 被判断为 busy；随后 `start B → complete B` 被拒绝为重叠。这证明了候选与该参考的覆盖差异，**没有证明本机那次历史重叠就是此原因，也没有验证当前 Desktop 的该事件形状/终止语义**。

先在本机核对历史重叠前后的最小生命周期片段及当前来源：是否确有未识别的终止事件，是否携带可关联 turn ID。如果确认支持且语义吻合，补对应解析与回归；只有证据表明生命周期已结束才能解除它的占用判断。若现场不存在此事件或语义不同，明确排除这条根因线索，不让它变成额外验收工程。不得删除历史或把任意未知事件当作结束。

## 同范围接续

1. 先修 F1，核对 F2。历史记录不能证明当前空闲，并不等于已经证明目标现在忙碌。此时保留待办是正确动作；也不能把旧历史的不完整永久定义成宿主忙碌。
2. 如果确认历史仍无法判定当前状态，支持只读核定并实现一个**指定原目标的最小原生状态快照**。先证明哪个字段表示当前活动回合/忙闲，如何与实际 owner、conversation、已核对的 cwd 及这次查询的 revision/请求关联。complete-history 只返回 revision 或一份完整历史，本身都不是 idle 证明；旧广播也不能当新快照。字段可以来自已验证的关联查询，不要求同一帧凭空具备不存在的字段。
3. 将“当前能否发送”与“历史批次/回合如何关联”分开。若确有权威当前快照，旧记录保留为历史证据，不能继续因同一旧缺口无条件否定当前状态；同时更新发送前检查与后续观察路径，避免只绕过入口、observe 仍被整段旧历史阻断。只接必要字段和该目标事件，不扩为全聊天订阅或通用遥控框架。没有可证明的当前状态契约时，返回具体缺口。
4. 条件解决后继续原来一个合成文件/批次的一次真实小试。先核对交接后没有新的发送，短时间内保持该目标没有其他写入者，发送前重查目标及状态。没有原子 idle-CAS 的限制应继续披露；它不单独增加“必须先实现通用原子队列”的小试门槛。目标确实忙碌或状态仍不明则保留暂停；已接受/结果不明只核对原尝试。核对原聊天、实际读取工具、结果内容和回合关联，Hook 未自然覆盖单列。
