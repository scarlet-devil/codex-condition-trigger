2. **保留核心/适配器分离，在聊天适配侧准备默认关闭的加载接口。** 只读 inspect 继续只读；打开原聊天是显式、可替换的动作。已可用时跳过导航。真正发现 owner 缺失时，候选采用准确既有 thread 的原生导航入口，打开后重新验证 thread/cwd、当前 owner 与 idle，再由原投递流程决定是否发送。加载器不接收业务 prompt，不新建替代聊天，不另起执行宿主或覆盖设置。不要复制旧版本固定安装路径和整包哈希作为永久兼容门槛。
