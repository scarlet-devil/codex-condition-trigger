## 判断与本阶段取舍

研究正确区分了三个问题：准确聊天 ID 的路由表达、目标窗口的选择、该窗口内实际 owner 的可用性。普通深链接在所查安装上选择导航主窗口；内部另开窗口链明确 show/focus。因此，不能把深链接当作保持主窗口当前聊天的专用窗口后端，也不应继续猜测 newWindow/focus 等参数。

接受“短暂出现/聚焦后最小化”作为**本次监督候选验证**的范围。这沿用红魔上一轮提出的“另开新窗口到最小化新窗口，直接后台最好”目标；无需为同一个备选方案再次请红魔选择。完全后台保留为偏好，不再阻塞此小试。这里没有替红魔接受未知时长的长期前台打扰：先记录真实影响，再判断正式采用。

当前无需继续扩大后台入口研究，或新增常驻焦点恢复器。Windows 对 [SetForegroundWindow](https://learn.microsoft.com/en-us/windows/win32/api/winuser/nf-winuser-setforegroundwindow) 有调用限制，即使满足条件也可能拒绝。自动恢复旧前台不是本次硬门槛；用户已主动切换窗口时，不抢回旧焦点。短暂聚焦、主窗口聊天被替换和操作错误窗口是不同后果，必须分别记录。

侧栏 Ctrl 分支有实际源码线索，但受开关和事件落点过滤影响。优先检查准确目标行可见的“另开窗口”上下文菜单；若没有可用的明确菜单，再核对 Ctrl 分支的真实可操作区域。采用实际可靠的一条入口，不同时扩建多条后端，也不把“Ctrl 点击任意标题”写成保证。
